## 핵심만 3가지

### 1. README를 따라 하면 모델이 고장난 것처럼 보입니다

README가 권장한 JSON 프롬프트 형식이 평가에서 실제로 쓴 형식과 달랐습니다. 그대로 따라 하면 **공백만 64토큰** 나옵니다. 평가에 쓴 형식을 넣으면 바로 유효한 JSON이 나옵니다. 노력 대비 손해가 가장 큰 항목이라 이것부터 고쳤습니다.

같은 이유로 웹 UI 기본 데모도 바꿨습니다. 원래 기본값이 16자리 코드 복사였는데, 모델 카드가 스스로 "retrieval exact 1/100"이라 밝힌 바로 그 취약점이라 설치 후 첫 클릭에서 FAIL이 떴습니다. 짧은 코드로 바꾸니 통과합니다.

### 2. `repetition_penalty`가 아예 동작하지 않고 있었습니다

1.0을 넘기면 무조건 크래시합니다. CLI·API·웹 UI 어디서 써도요.

```
RuntimeError: Inplace update to inference tensor outside InferenceMode is not allowed.
```

`prefill`/`decode_step`이 `@torch.inference_mode()`라 로짓이 inference tensor인데, `.float()`는 이미 fp32면 아무것도 안 하고 원본을 그대로 돌려줍니다. 거기에 in-place 쓰기를 하니 터집니다. **bf16에서는 `.float()`가 진짜로 새 텐서를 만들기 때문에 우연히 동작했고**, fp32(=CPU 기본값)에서는 항상 깨져 있었습니다.

고치고 나니 더 흥미로운 게 나왔습니다. 페널티가 반복은 잡는데 **정확 복사를 깨뜨립니다.** 구현이 프롬프트 토큰까지 페널티를 먹이는데, retrieval은 프롬프트의 식별자를 그대로 베끼는 과제거든요. 모델이 해야 할 일을 정확히 억제하고 있었습니다.

그래서 `--repetition-scope generated` 옵션을 추가했습니다(기본값은 기존 그대로).

| 설정 | 반복률 | retrieval | JSON |
|---|---:|---|---|
| penalty 1.00 | 0.463 | OK | OK |
| penalty 1.10, scope=all (기존) | 0.279 | **깨짐** | OK |
| **penalty 1.10, scope=generated** | **0.232** | **OK** | **OK** |

반복률이 절반으로 떨어지면서 두 능력 다 살아남습니다. 지금 바로 쓸 수 있습니다.

### 3. 가장 중요한 것 — 모델이 너무 큽니다

```
파라미터    426,806,356
학습 토큰   528,905,026
토큰/파라미터      1.24      ← Chinchilla 최적은 약 20
```

지금 크기를 제대로 학습시키려면 8.5B 토큰, 보고된 처리량 기준 **48.6일**이 걸립니다. 즉 **가진 GPU로는 학습을 끝낼 수 없는 크기**를 고른 겁니다. 그래서 1.24에서 멈출 수밖에 없었고, 지금 보이는 약점 대부분이 거기서 나옵니다.

같은 컴퓨트로 최적점을 계산하면 **`dim=768, n_layers=12, n_heads=12`** (116M 파라미터, 2.3B 토큰, **약 3.6일**)입니다.

작은 쪽이 지금 것보다 성능이 좋을 가능성이 높습니다. 실제로 지금 426M 모델이 held-out bits-per-byte에서 **자기보다 3.4배 작은 GPT-2 124M에게 지고 있습니다.** 크기가 부족해서가 아니라 학습이 부족해서입니다.

다만 이건 나쁜 소식만은 아닙니다. 같은 비교에서 **단순 서사와 Python은 GPT-2 medium(355M)까지 이깁니다.** 파라미터당 1.24 토큰으로 그건 나올 만한 결과가 아니에요. 좁은 분포에 예산을 집중하면 이만큼 나온다는 걸 보여줍니다.
