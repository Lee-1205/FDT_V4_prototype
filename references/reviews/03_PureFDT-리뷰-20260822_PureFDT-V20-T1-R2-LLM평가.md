# PureFDT V20 T1 R2 — 언어모델로서의 평가

**평가일** 2026-08-22
**방법** 동일 텍스트·동일 지표로 GPT-2와 직접 비교. 평가 텍스트는 이 테스트를 위해 새로 작성했으므로 **어느 모델도 학습한 적 없습니다.**
**기준** bits per byte(BPB). 토크나이저가 다르면 perplexity는 비교 불가이지만 BPB는 분모가 원문 바이트라 비교 가능합니다.

---

## 0. 먼저 알아야 할 숫자 하나

```
파라미터      426,806,356
학습 토큰     528,905,026   (누적 계보 카운터)
토큰/파라미터        1.24
```

Chinchilla 최적은 파라미터당 **약 20 토큰**입니다. 이 모델은 **1.24**입니다.

즉 이 체크포인트는 조금 덜 학습된 게 아니라 **한 자릿수 배수 이상 덜 학습됐습니다.** 아래 나오는 거의 모든 약점이 여기서 파생됩니다. 그리고 중요한 함의가 하나 있습니다 — **이 체크포인트로는 아키텍처를 평가할 수 없습니다.** 측정되는 건 아키텍처가 아니라 학습 예산입니다.

비교 대상으로 고른 GPT-2 medium(355M)은 파라미터가 가장 비슷하면서 토큰/파라미터가 이 모델보다 한 자릿수 이상 큽니다. 그러니 아래 표는 "FDT vs Transformer"가 아니라 **"학습 예산 1.24 vs 충분히 학습된 모델"**로 읽으셔야 합니다.

---

## 1. Bits per byte — 낮을수록 좋음

| 텍스트 | PureFDT 426M | GPT-2 124M | GPT-2 medium 355M |
|---|---:|---:|---:|
| 일반 산문 | 1.593 | 1.356 | **1.197** |
| 기술 산문 | 1.667 | 1.393 | **1.240** |
| 단순 서사 | **1.058** | 1.312 | 1.144 |
| Python 코드 | **1.090** | 1.424 | 1.153 |
| 구조화 JSON | 2.545 | 1.916 | **1.851** |
| **전체 (바이트 가중)** | 1.550 | 1.453 | **1.284** |

읽는 법이 두 가지입니다.

**나쁜 쪽** — 전체 평균에서 **자기보다 3.4배 작은 GPT-2 124M에게 집니다** (1.550 vs 1.453). 426M 모델이 124M에게 지는 건 정상이 아닙니다. 토큰/파라미터 1.24가 무슨 뜻인지 그대로 보여주는 숫자입니다.

**좋은 쪽** — 그런데 **단순 서사와 Python에서는 GPT-2 medium까지 이깁니다.** 이 두 영역은 자체 held-out에서도 가장 좋았던 버킷입니다(perplexity 7.6, 6.5). 즉 우연이 아니라 학습 분포를 정확히 반영합니다.

결론: **이건 범용 base LM이 아니라 좁게 특화된 모델입니다.** 학습 분포 안에서는 예산 대비 놀랍도록 경쟁력 있고, 밖에서는 훨씬 작은 모델에게도 밀립니다.

JSON 2.545는 따로 짚을 만합니다. 릴리스가 "JSON syntax valid 50/50"을 내세우지만 BPB로는 세 모델 중 압도적 꼴찌입니다. **템플릿 하나의 표면 형태를 외웠을 뿐 JSON을 모델링하지 못한다**는 뜻이고, 실제로 값 일치가 0/50인 것과 정확히 맞아떨어집니다.

### 토크나이저 부수 관찰

| | PureFDT (24K) | GPT-2 (50K) |
|---|---:|---:|
| 일반 산문 바이트/토큰 | 4.34 | 4.61 |
| JSON 바이트/토큰 | 1.90 | 2.26 |

PureFDT 토크나이저가 일관되게 **덜 압축적**입니다. 같은 문장을 더 많은 토큰으로 쪼갭니다. 그래서 raw perplexity로 비교하면 이 모델이 실제보다 유리하게 보입니다. BPB로 봐야 하는 이유입니다.

## 2. 자유 생성 — 여기서 무너집니다

동일 프롬프트, greedy, 48토큰. trigram 반복률(낮을수록 좋음).

| | PureFDT 426M | GPT-2 124M | GPT-2 medium 355M |
|---|---:|---:|---:|
| 평균 반복률 | **0.616** | 0.365 | 0.343 |

greedy는 원래 모든 모델을 반복에 빠뜨립니다. GPT-2도 0.34-0.37로 깨끗하지 않습니다. 그런데 PureFDT는 **거의 두 배**입니다.

실제 출력을 보면 패턴이 아주 선명합니다.

**"Three primary colors are red, blue, and"**
```
PureFDT: ' yellow.\nThe color of the color of the color of the color of...'
```
**첫 토큰은 맞혔습니다.** `yellow`가 정답입니다. 그리고 바로 무너집니다.

**"The capital city of France is"**
```
PureFDT:  ' the city of the city of the city of the city of...'   반복률 0.93
GPT-2 124M: ' the capital of the French Republic, and the capital of...'
```
Paris를 시도조차 하지 않습니다. 자체 평가 factual 1/50이 이 모습입니다.

**"Once upon a time there was a small red boat that"**
```
PureFDT: ' was filled with water. The boat was very happy and it had a
          big adventure. The boat sailed for days and days...'   반복률 0.33
GPT-2 medium: 반복률 0.57
```
여기서는 **세 모델 중 가장 좋습니다.** 문장이 자연스럽고 반복도 가장 적습니다. TinyStories 분포가 이 모델의 홈그라운드입니다.

---

## 3. 진짜 병목은 능력이 아니라 지속입니다

자체 평가에도 같은 신호가 이미 있습니다.

| 지표 | 값 | 뜻 |
|---|---:|---|
| capability top-1 정확도 | **66.7%** | 다음 토큰 하나는 3분의 2를 맞힘 |
| capability sequence exact | **2.0%** | 그런데 문장 전체를 맞히는 건 50번에 한 번 |
| strict loop-free | 17/50 | 생성의 66%가 루프로 붕괴 |

그리고 가장 진단적인 대비가 이겁니다.

| 버킷 | teacher-forced perplexity | 자유 생성 반복률 |
|---|---:|---:|
| code_python | **6.5** (가장 좋음) | **0.666** (가장 나쁨) |
| tinystories | 7.6 | 0.093 |
| fineweb | 83.7 | 0.502 |

**Python은 teacher forcing에서 가장 잘하면서 자유 생성에서 가장 심하게 무너집니다.** 이건 전형적인 exposure bias 신호입니다. 정답이 앞에 깔려 있으면 다음 토큰을 잘 고르는데, 자기 출력을 다시 먹기 시작하면 궤도를 벗어나 같은 토큰으로 빨려 들어갑니다.

즉 **모델이 모르는 게 아닙니다.** 알고 있고, 첫 스텝은 맞히고(`yellow`, `Q7M2X9K6...`, `def clamp(value,`), 이어가지 못합니다. factual 1/50 · retrieval 1/100 · JSON 값 0/50 · Python AST 0/25는 서로 다른 네 개의 결함이 아니라 **하나의 결함이 네 군데서 드러난 것**으로 보입니다.

---

## 4. 그래서 LLM으로서 몇 점인가

**범용 언어모델로는 쓸 수 없습니다.** 사실 질의응답, 검색, 구조화 추출 전부 실용 수준 아래입니다. 모델 카드도 그렇게 적어놨고 그 판단이 맞습니다.

**하지만 실패작은 아닙니다.** 파라미터당 1.24 토큰으로 TinyStories 서사와 Python 구조에서 GPT-2 medium을 BPB로 이기는 건 그 예산에서 나올 만한 결과가 아닙니다. 좁은 분포에 예산을 집중하면 이만큼 나온다는 걸 보여줍니다.

**공정하게 말하면, 지금 이 체크포인트로는 FDT 아키텍처를 평가할 수 없습니다.** 토큰/파라미터가 Chinchilla의 16분의 1인 상태에서 나온 모든 수치는 아키텍처가 아니라 예산을 측정한 것입니다. 아키텍처 주장을 하려면 같은 토큰 예산으로 학습한 dense transformer와 비교해야 하는데, 그건 이미 `TECHNICAL_OVERVIEW.md`가 속도 축에서만 해놨고 품질 축에서는 안 했습니다.

---

## 5. 다음에 뭘 하면 좋을지

우선순위 순입니다.

1. **토큰 예산을 늘리세요.** 다른 무엇보다 먼저입니다. 파라미터를 절반(200M)으로 줄이고 같은 컴퓨트로 토큰을 4배 쓰는 쪽이, 지금 크기로 조금 더 학습하는 것보다 거의 확실히 낫습니다. 1.24는 너무 낮아서 다른 실험의 신호를 전부 덮습니다.

2. **매칭된 품질 대조군을 만드세요.** 동일 토큰 예산·동일 데이터·동일 토크나이저로 dense transformer를 학습해 BPB를 비교하세요. 속도 벤치마크는 이미 있고, 품질 쪽 대조군이 없어서 "FDT가 언어모델링에 쓸 만한 아키텍처인가"라는 핵심 질문에 답을 못 하고 있습니다.

3. **반복 붕괴를 정면으로 다루세요.** 지금 가장 큰 단일 결함입니다. 당장 싼 것부터: 추론에서 `--repetition-penalty`(이미 구현돼 있음, 1.0~3.0)를 1.05~1.15로 올려 반복률이 얼마나 떨어지는지 측정. 그다음 학습 쪽에서 EOS 감독 강화, 자기 출력을 먹이는 scheduled sampling 계열.

4. **평가에 BPB를 추가하세요.** 지금 지표는 전부 자기 토크나이저 기준이라 외부 모델과 비교가 안 됩니다. BPB 한 줄 추가하면 "GPT-2 대비 어디쯤인가"에 매번 답할 수 있습니다.

5. **위치 임베딩을 RoPE로 바꾸세요.** [수정 내역 8-3](PureFDT-V20-T1-R2-수정내역.md)에서 다룬 대로, 2,048 상한이 이 아키텍처의 장점이 드러나는 구간을 잘라내고 있습니다.

## 부록: 재현 방법

```powershell
# 평가에 쓴 기준 모델
$env:HF_HOME='C:\Users\KING\hf'
.venv\Scripts\python.exe -c "from transformers import AutoModelForCausalLM; AutoModelForCausalLM.from_pretrained('gpt2-medium')"
```

BPB는 각 텍스트를 두 모델에 각각 통과시켜 `sum(-log p(token_i | prefix)) / ln(2) / len(text.encode('utf-8'))`로 계산했습니다. 첫 토큰은 예측 대상이 아니므로 두 모델 모두 동일하게 제외했습니다. 반복률은 릴리스 자체 평가와 같은 trigram 중복 비율 정의를 썼습니다.
