
기존 FDT v4 core 구조(RoPE, W64, fuzzy anchor 256/top8, Exact Memory)는 변경하지 않는다.

추가할 학습 최적화:

1. Dynamic Loss Balancing
- row 수가 아니라 실제 supervised-token 수와 loss contribution 기준으로
  natural / knowledge / exact / recovery / long-context 비중을 자동 보정.
- 한 영역이 gradient를 과점하지 못하도록 cap 적용.

2. Exact-Memory Curriculum
- 4→8→16→32→64 token 순으로 exact-copy 난이도 증가.
- 숫자, random string, UUID/hash, JSON value, code identifier를 균형 학습.
- 처음부터 긴 문자열만 학습시키지 않는다.

3. Prefix-Recovery Curriculum
- 초기에는 정상 teacher forcing 위주.
- 학습 진행에 따라 model-generated/corrupted prefix 비율을 점진 증가.
- 한 번의 오출력 이후 정상 trajectory로 복귀하는 능력을 학습.

4. Loop Unlikelihood Loss
- 비정상적인 반복 n-gram에만 추가 loss 적용.
- 코드/숫자/Exact Copy의 정상 반복은 제외.
- inference 3-gram block에만 의존하지 않도록 한다.

5. Mixed Context Curriculum
- 대부분 2K, 일부 4K, 소량 8K/16K.
- 긴 context 비율은 초반 낮게 시작해 후반 증가.
- long sample 때문에 전체 학습 throughput이 지나치게 떨어지지 않게 제한.

6. Sequence Packing
- 짧은 natural/knowledge 샘플은 가능한 한 context에 packing.
- sample boundary와 EOS/loss mask는 엄격히 유지.
- padding 연산 낭비 최소화.

7. Selective Freeze / Unfreeze
- 초기 v4 안정화 단계에서는 검증된 fuzzy router/anchor를 우선 보존.
- RoPE/Exact Memory/new objectives가 안정된 뒤 필요한 경우에만 점진 unfreeze.
- routing regression을 매 단계 검사.

8. Capability-balanced Batch
- 같은 batch가 특정 Python/JSON/Exact 유형으로 몰리지 않게 category mixture 보장.
- row count뿐 아니라 실제 target token 수 기준으로 배치 균형화.

구현 우선순위:

1. Decode Fast Path
- token당 Python loop / tensor allocation 최소화
- decode용 buffer/state 사전 할당 및 재사용
- 불필요한 clone/cat/reshape/device sync 제거
- static shape 가능한 경로 고정

2. torch.compile
- inference 전용 compiled path 분리
- reduce-overhead 계열 설정 시험
- eager 대비 correctness와 latency A/B 측정

3. CUDA Graph
- batch/context state shape가 고정 가능한 decode path capture
- launch overhead 감소
- eager/compile/graph를 각각 독립 benchmark

4. Fuzzy Router Fusion
가능하면 다음을 한 경로로 묶는다:

→ router projection
→ cosine
→ top-k
→ membership softmax

수학적 routing 결과는 바꾸지 않는다.

5. Anchor Memory Fusion
가능하면:
anchor gather
→ base/recent summary
→ weighted reduction
→ numerator/mass update
를 fuse한다.

6. Exact Memory Fast Path
- 전체 context scan 금지
- 기존 top8 anchor index 재사용
- bounded candidate chunks
- retrieval 결과 cache
- Copy Cursor 동안 재검색 금지

7. Copy Fast Path
Exact span이 확정되면:
- sampling/top-k/top-p 생략
- 불필요한 vocabulary decision 생략 가능 여부 검토
- 긴 span은 token-by-token decode보다 batched mini-prefill/state ingestion이 빠른지 비교
- copied tokens는 이후 FDT state에 정확히 반영되어야 함

8. LM Head 최적화
- Copy Mode에서는 full-vocab LM head 계산이 정말 필요한지 확인
- 필요 없으면 안전하게 우회
- normal generation에서는 기존 결과 유지

9. Cache 최적화
- local KV는 W64 고정 ring buffer 가능 여부 검토
- anchor numerator/mass in-place update
- 매 token concat 금지
- RoPE position offset 정확성 유지

10. 3-gram/repetition logic
- main speed/quality benchmark에서는 OFF
- 별도의 safety/generation diagnostic으로만 측정
- repetition penalty 없이도 모델 자체 품질이 유지되는지 평가

# Additional Inference Optimizations

11. Weight Quantization
- BF16/FP16 baseline과 INT8/INT4 weight-only inference를 비교한다.
- 품질, exact-copy, cache integrity가 유지되는 경우에만 채택한다.
- 누적되는 fuzzy anchor numerator/mass는 무리하게 저정밀화하지 않는다.
- batch1 decode에서 weight-memory-bandwidth 감소 효과를 측정한다.

12. Fixed-W64 Attention Kernel
- local attention window가 항상 W=64라는 점을 이용한다.
- generic attention 대비 W64-specialized Triton/CUDA kernel의 가치가 있는지 profiler로 확인한다.
- 수학적 attention 결과는 변경하지 않는다.

13. Continuous Batching
- batch 1/2/4/8 및 가능한 더 큰 batch에서 long-context throughput을 측정한다.
- requests/sec, VRAM/request, tok/s를 optimized Transformer와 비교한다.
- FDT의 bounded local/semantic state가 long-context batching에서 실제 이점인지 검증한다.

14. RoPE Fast Path
- 16K position용 rotary cache를 사전 계산한다.
- decode마다 sin/cos를 재생성하지 않는다.
- incremental position offset correctness를 유지한다.

15. Exact-Memory Storage Benchmark
- 2K/4K/8K/16K에서 raw token memory, index metadata, retrieval cache가 차지하는 실제 메모리를 측정한다.
- Transformer KV cache와 동일 조건에서 별도로 비교한다.

16. Prefill Optimization
- 8K/16K sparse causal prefix scan을 별도로 profile한다.
- allocation, scatter/gather, synchronization 병목을 찾는다.
- 가능한 경우 fused/parallel prefix scan을 시험한다.
- decode 최적화 결과와 섞지 않는다.

최종적으로 다음 세 지표를 모두 보고한다:

B. Long-context VRAM
C. Multi-request throughput
